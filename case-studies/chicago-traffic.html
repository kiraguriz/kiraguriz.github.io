01 / Problem

A big table answers nothing by itself.

The dataset is a 68 MB SQLite file of intersections, red-light cameras, speed cameras, and daily violation counts — far too much to read by hand and easy to summarize wrongly.

The task was to ask real questions of it: which intersections offend most, how violations move year over year, and where a given street's cameras actually stand on a map.

02 / Approach

Three rules I held to.

① Push work into SQL

Joins, grouping, and percentage math run in the query, not in Python loops over fetched rows.

② Parameterize everything

Every user input — intersection, street, year, camera ID — binds as a parameter, so wildcards work and injection doesn't.

③ Make it legible

Results print as ranked, formatted tables and, on request, as time-series and geographic plots people can actually read.

03 / System

How a question becomes a chart.

A menu choice maps to a parameterized SQL query; rows come back formatted, and an optional matplotlib step turns them into a plot.

queryviolations per intersection, by year
SELECT Intersections.Intersection,
       SUM(RedViolations.Num_Violations) AS total
FROM Intersections
JOIN RedCameras
  ON Intersections.Intersection_ID = RedCameras.Intersection_ID
JOIN RedViolations
  ON RedCameras.Camera_ID = RedViolations.Camera_ID
WHERE strftime('%Y', RedViolations.Violation_Date) = ?
GROUP BY Intersections.Intersection
ORDER BY total DESC;

Nine analyses over five tables using inner joins, aggregation, correlated subqueries, and strftime date grouping.
