01 / THE PROBLEM

A report touches the map, the form, and the details at once.

Release 1 had to load five fictional sample reports, refuse a report without a location or litter level, save valid ones in the browser, and mark a report cleaned, with both changes still there after a restart. Those rules cross every screen, so they needed one owner and one source of truth.

What I owned

The report data layer (CS442-12): Zod validation, a Dexie/IndexedDB repository with seeded reports, and shared React subscriptions. I wrote the Release 1 and Release 2 scenarios with their acceptance criteria, reviewed teammates’ pull requests in a Jira-tracked Scrum process, and led the V5 map-first responsive redesign (CS442-39).

BUILT WITHReact 19 / TypeScript / Vite / Leaflet / Dexie / Zod / Vitest

02 / KEY DECISIONS

The choices
behind the work.

Implementation is a series of decisions. These are the ones that shape this project.

01

Reject bad coordinates instead of guessing.

A shared Zod schema checks latitude and longitude as finite numbers in range. Missing, blank, null, and string coordinates are rejected rather than coerced to zero, while a real zero stays valid. Each issue names its field, so the form can point at the exact problem.

THE TRADEOFFA stricter form needs clearer errors: a blank submit moves focus to an error summary instead of failing silently.

02

One repository, shared subscriptions.

Screens read reports through one repository interface backed by Dexie/IndexedDB, and a shared subscription keeps the map, list, form, and details view in step. Mark as Cleaned shows success only after the write resolves, and keeps the previous status with a retry message if it fails.

THE TRADEOFFRelease 1 data lives in each browser, so two people do not see each other’s reports. The interface leaves room to swap in a shared service later.

03

Write the scenario before the code.

Both release scenarios walk through a fictional volunteer and end in a pass or fail checklist. They also say what is out of scope: in Release 1, Mark as Cleaned changes a status and does not create a cleanup event. Release 2 adds accounts, photos, and cleanup events, and requires the service, not just the interface, to restrict who can create events.

THE TRADEOFFExplicit boundaries mean saying no to features early, but they gave the team something concrete to test against.

04

Keep the map first on every screen size.

The redesign lets the map fill the screen. On desktop, a report list and a details panel sit beside it; on phones, the list becomes a draggable bottom sheet. Markers are reachable by keyboard, focus moves into the details and back, and reduced-motion settings turn off transitions.

THE TRADEOFFMore layouts mean more states to check, so each one was inspected in a real browser at several widths.
