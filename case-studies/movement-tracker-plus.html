01 / THE PROBLEM

Advice is only as good as the rep count under it.

A camera coach fails quietly: if it miscounts a set, every suggestion after that is built on the wrong numbers. I wanted the measurements to come from the phone, where they can be tested, and the language model to explain them without being allowed to change them.

What I owned

Everything, as a native rewrite with no code carried over from the class project: the SwiftUI app, the MotionCore rep-counting engine, the Muse integration, Apple Health sync, a Live Activity rest timer, Siri App Shortcuts, English and Simplified Chinese localization, and the Cloudflare Worker that holds the API keys.

BUILT WITHSwift 6 / SwiftUI / Apple Vision / GRDB / HealthKit / ActivityKit / Muse / Cloudflare Workers

02 / KEY DECISIONS

The choices
behind the work.

Implementation is a series of decisions. These are the ones that shape this project.

01

Measure on the device. Let the model explain.

MotionCore turns Vision body-pose frames into reps, partial reps, depth, tempo, and velocity loss: a confidence gate, One-Euro smoothing, side locking, and a time-based rep segmenter driven by JSON exercise specs. Muse receives those numbers as facts it must not recount. Reviews come back through strict JSON schemas, and a review that cites a rep that does not exist is rejected. If Muse cannot answer, the app shows an on-device review and labels it.

THE TRADEOFFThe model cannot rescue a counting mistake, so the engine carries most of the risk and most of the tests.

02

Teach a new exercise, then prove it.

You perform a few reps and say how many you did. The app replays the recording through the engine and saves the movement as a counted exercise only when the replay reproduces that number. Form checks Muse suggests are kept only if every rep still counts with them in place.

THE TRADEOFFSome demonstrations end up as log-by-hand exercises. That is better than a counter that is wrong from the first set.

03

Keep API keys off the phone.

The app calls a Cloudflare Worker, never Meta directly. The Worker holds the Muse and USDA keys as secrets, accepts anonymous per-install tokens, allows only approved models, caps reasoning effort, output tokens, and body size per feature, and uses a SQLite Durable Object for atomic per-install and global daily budgets, plus a kill switch.

THE TRADEOFFRequest budgets limit how much can be spent; they are not an exact dollar cap.

04

Make Apple Health writes survive interruptions.

A saved workout, meal, or weight and its Health sync intent commit in the same SQLite transaction, so a crash cannot drop the sync. With partial Health permission, allowed types are written and the rest stay queued until the user grants them.

THE TRADEOFFMore states to model and test, in exchange for not losing data the user expects to see in Health.

Scope of this evidence

The captures replay generated pose clips in the Simulator. The rep counter has been checked against generated motion only (24 of 24 synthetic clips counted exactly), and the engine was tuned on that generator, so this is a regression check, not a measure of accuracy on people. Real-person accuracy is not yet measured.

WHAT I TAKE FORWARD

An AI feature is easier to trust when the model is never the source of truth for the numbers it talks about.
